# 知识点 Demo 02：张量数据与内存管理（OrtValue / OrtMemoryInfo / 形状）

- **关联知识点**：算子输入输出 · 数据载体 · 内存位置
- **核心问题**：算子在 `Run` 中加工的对象到底是「什么」？为什么不能直接传普通数组？

---

## 1. 为什么需要 `Ort::Value`

一个矩阵/数组在电脑里可以只是「一块连续内存」。但推理引擎里的张量还需要描述**它到底是什么**：

- 数据在**哪里**（CPU 内存？GPU 显存？分配器类型？）
- 数据是什么**类型**（float32 / float16 / int32 …）
- 数据是几个**维度**、每个维度多长（形状 shape）
- 数据**指针**

`Ort::Value` 就是「张量 + 元信息」的包装。它有两个关键组成部分：

| 组成 | 作用 | 头文件类型 |
|------|------|-----------|
| 数据本身 + 形状 + 数据类型 | 张量内容与结构 | `Ort::Value` / `TensorTypeAndShapeInfo` |
| 内存信息 | 数据放在哪、怎么分配 | `Ort::MemoryInfo` |

## 2. `Ort::MemoryInfo`：数据的位置与分配方式

`Ort::MemoryInfo` 描述一块内存的「出处」。最重要的一种：**CPU 内存**。

```cpp
// 位置：CPU；分配器：arena 池化分配；内存类型：默认（张量数据）
auto cpu_mem = Ort::MemoryInfo::CreateCpu(OrtArenaAllocator, OrtMemTypeDefault);
```

两个参数的含义（对应 [onnxruntime_cxx_api.h](file:///workspace/onnxruntime1.26.0-win/onnxruntime_cxx_api.h) 的 `MemoryInfo::CreateCpu`）：

- **分配器类型 `OrtAllocatorType`**：`OrtArenaAllocator`（带内存池/复用）或 `OrtDeviceAllocator`（每次直接分配）。
- **内存类型 `OrtMemType`**：`OrtMemTypeDefault`（普通张量数据）、`OrtMemTypeCPUInput`/`OrtMemTypeCPUOutput`（需要 CPU 可访问的输入/输出）等。

> 显卡推理时，`Ort::MemoryInfo` 会指向 CUDA 分配器等非 CPU 位置。这也是后面「Demo 04：EP 切换」的基础。

## 3. `Ort::Value`：把数据包装成张量

用 `Value::CreateTensor<float>` 把「裸指针数组」变成张量：

```cpp
std::vector<float> data(1 * 3 * 224 * 224);
std::vector<int64_t> shape{1, 3, 224, 224};           // 维度：NCHW

Ort::Value tensor = Ort::Value::CreateTensor<float>(
    cpu_mem,          // 内存信息
    data.data(),      // 数据指针
    data.size(),      // 元素个数
    shape.data(),     // 形状数组
    shape.size());    // 形状维数(4)
```

**反向读取**：从 `Ort::Value` 卸下元信息。

```cpp
const auto info = tensor.GetTensorTypeAndShapeInfo();  // 张量类型与形状

auto shape   = info.GetShape();           // std::vector<int64_t>{1,3,224,224}
auto element_count = info.GetElementCount(); // 1*3*224*224
ONNXTensorElementDataType dtype = info.GetElementType(); // 元素枚举类型

float* p = tensor.GetTensorMutableData<float>();  // 拿到可写数据指针
```

对应头文件中的类（[onnxruntime_cxx_api.h](file:///workspace/onnxruntime1.26.0-win/onnxruntime_cxx_api.h)）：
- `Ort::Value`（张量值）
- `Ort::TensorTypeAndShapeInfo`（`GetShape()`、`GetElementType()`、`GetElementCount()`）

## 4. 张量生命周期与所有权的两种模式

- **用户提供 buffer**（`CreateTensor`）：数据 `data` 由调用方持有，ORT 借用它，**不负责释放**。
- **ORT 分配**（`Value::CreateTensor(OrtAllocator*, shape, shape_len)`）：ORT 自己分配内存并管理所有权，返回的 `Ort::Value` 析构时释放内存。

掌握这个区别很关键：**谁分配、谁释放**。这也决定了在 `Run` 前后数据能否继续被复用。

## 5. 最小示例：张量包装与读取

```cpp
#include <onnxruntime_cxx_api.h>
#include <vector>
#include <cstdio>

int main() {
    // CPU 内存信息
    auto mem_info = Ort::MemoryInfo::CreateCpu(OrtArenaAllocator, OrtMemTypeDefault);

    // 打包输入
    std::vector<float> x(28*28, 1.f);
    std::vector<int64_t> shape{1, 1, 28, 28};
    Ort::Value in = Ort::Value::CreateTensor<float>(
        mem_info, x.data(), x.size(), shape.data(), shape.size());

    // 读出元信息
    const auto tinfo = in.GetTensorTypeAndShapeInfo();
    auto out_shape = tinfo.GetShape();                 // {1,1,28,28}
    auto count     = tinfo.GetElementCount();          // 784
    float* p       = in.GetTensorMutableData<float>(); // 指向 x

    printf("rank=%zu count=%zu first=%f\n", out_shape.size(), count, *p);
    return 0;
}
```

## 6. 与仓库头文件的对应关系

| 概念 | 头文件类型 / 函数 |
|------|------------------|
| 内存信息 | `Ort::MemoryInfo`、`MemoryInfo::CreateCpu(OrtArenaAllocator, OrtMemTypeDefault)` |
| 张量值 | `Ort::Value`、`Value::CreateTensor<float>(mem,data,n,shape,shape_len)` |
| 类型与形状 | `TensorTypeAndShapeInfo::GetShape / GetElementType / GetElementCount` |
| 数据指针 | `Value::GetTensorMutableData<T>()` |

## 7. 自测题（掌握本知识点）

1. `CreateCpu(OrtArenaAllocator, OrtMemTypeDefault)` 中两个参数各控制什么？`OrtMemTypeCPUInput` 常用于什么场景？
2. 创建一个形状为 `{2, 3}` 的 int64 张量，数据给你一个 `std::vector<int64_t>`，写出 `CreateTensor` 的完整调用。
3. 如果用 `Value::CreateTensor` 传入自己开的 buffer，ORT 会把这块内存释放吗？它在什么时候不该被 free？（提示：所有权）
4. 为什么 GPU 推理时，`Ort::MemoryInfo` 和输入数据在 CPU 的示例不同？（提前体会 Demo 04 的内容）

<details>
<summary><b>参考答案</b></summary>

1. 第一个参数 **`OrtAllocatorType` 控制内存的分配方式**：`OrtArenaAllocator`（带内存池、可复用小块）或 `OrtDeviceAllocator`（每次直接向设备申请）。第二个参数 **`OrtMemType` 描述这块内存的类型 / 可访问性语义**（`OrtMemTypeDefault`＝EP 设备端的普通张量数据；`OrtMemTypeCPUInput/CPUOutput`＝要求该算子的输入/输出位于 **CPU 可访问的内存**）。`OrtMemTypeCPUInput` 常用于**GPU 推理中某些算子（往往是无对应 GPU Kernel、或必须回 CPU 读数据的算子）需要跨到 CPU 拿数据**的边界场景，它约束的是"这个 Kernel 的输入必须是 CPU 可访问"，而不是字面上的"把张量放 CPU"。
2.
```cpp
std::vector<int64_t> data(2 * 3, 1);      // 6 个元素；注意第二个参数是 int64_t
std::vector<int64_t> shape{2, 3};
Ort::Value t = Ort::Value::CreateTensor<int64_t>(
    mem_info, data.data(), data.size(), shape.data(), shape.size());
```
   （小坑：`vector<int64_t>(n, 1.0f)` 里 `1.0f` 会隐式转成 `int64_t` 的 `1`，能编译但最好直接写 `1`。）
3. **不会**。`Value::CreateTensor` 用用户提供的 buffer 时是"借用"，**所有权（分配与释放）仍在调用方**，ORT 不负责释放。它不该被 free 的时间点是：**该张量被 ORT 使用的期间**（尤其是 `Run` 执行用到它的时候），必须在 `Run` 完成、且不再被引用后，调用方才可以释放。
4. 变化的是**内存位置这一部分，而不是形状/数据类型**。GPU 推理时，`Ort::MemoryInfo` 指向 **CUDA 设备内存分配器**（如 CUDA EP 的分配器），而非 CPU：输入数据的"家"变成了显存，要么数据一开始就在设备端，要么由 ORT 在 CPU↔GPU 之间拷贝。至于形状 `{1,3,224,224}`、类型 float32 这些语义信息，并不因为跑在 GPU 就改变。

</details>
