# 知识点 Demo 01：ONNX Runtime 完整推理流程

- **关联知识点**：推理流程 · 算子执行入口 · Session 生命周期
- **核心问题**：一个模型文件从磁盘到张量输出，中间的每一步是什么？算子在哪个环节被「真正执行」？

---

## 1. 核心概念：模型 = 图 = 算子集合

ONNX 模型文件（`.onnx`）本质上描述了一张**有向计算图**：

- **节点（Node）**：每个节点就是一个算子（如 `Conv`、`Relu`、`Add`、`Gemm`）。
- **边（Edge）/ 张量（Tensor）**：连接节点的数据，即输入、中间结果、输出张量。
- **拓扑顺序**：推理必须按照「输入→输出」的依赖顺序逐个执行节点。

![推理流程图(示意)](https://trae-api-cn.mchost.guru/api/ide/v1/text_to_image?prompt=diagram%20of%20a%20deep%20learning%20inference%20graph%2C%20nodes%20as%20operator%20squares%20labeled%20Conv%2C%20Relu%2C%20Add%2C%20Gemm%2C%20tensor%20edges%20as%20arrows%2C%20input%20tensor%20on%20left%2C%20output%20tensor%20on%20right&image_size=landscape_16_9)

推理（Inference）就是**按拓扑顺序逐个执行算子**，把输入张量加工成输出张量。ONNX Runtime 负责加载这张图、分配内存、调度执行。

## 2. 完整推理流程（5 个阶段）

用仓库头文件里的 API 对应每一步：

### 阶段 0：创建环境 `Ort::Env`
全局运行时环境，用于日志、线程池等。参见 [onnxruntime_c_api.h](file:///workspace/onnxruntime1.26.0-win/onnxruntime_c_api.h) 中的 `CreateEnv`。

```cpp
Ort::Env env(ORT_LOGGING_LEVEL_WARNING, "demo");
```

### 阶段 1：配置会话选项 `Ort::SessionOptions`
决定执行提供器（CPU/GPU）、图优化级别、线程数等。

```cpp
Ort::SessionOptions opts;
opts.SetGraphOptimizationLevel(GraphOptimizationLevel::ORT_ENABLE_ALL);
// 可选：追加 CPU / CUDA 执行提供器
// OrtSessionOptionsAppendExecutionProvider_CPU(opts, 1);
```

### 阶段 2：创建会话句柄 `Ort::Session`
把 `.onnx` 文件反序列化并**建图、做图优化、为每个算子绑定 Kernel（可执行实现）**。

```cpp
const char* model_path = "model.onnx";
Ort::Session session(env, model_path, opts);   // 离开 std::string 的 C 接口: CreateSession
```

> ⚠️ 关键认知：**此时还没有执行算子**，只是完成了「加载与编译」。Session 内部持有完整的算子调度计划。

### 阶段 3：准备输入 `Ort::Value`
每个输入都要被包装成 `Ort::Value`（张量 + 数据 + 形状 + 类型 + 内存位置）。这一步就是我们后面「知识点 Demo 02」的主角。

```cpp
std::vector<float> data(1 * 3 * 224 * 224);            // 假数据
std::vector<int64_t> shape{1, 3, 224, 224};
auto mem_info = Ort::MemoryInfo::CreateCpu(OrtArenaAllocator, OrtMemTypeDefault);
Ort::Value input = Ort::Value::CreateTensor<float>(mem_info, data.data(), data.size(), shape.data(), shape.size());
```

### 阶段 4：执行推理 `Run`
把输入交给 Session，Session 按拓扑顺序**逐个调用每个算子绑定的 Kernel**，得到输出 `Ort::Value` 数组。

```cpp
const char* input_names[]  = {"input"};
const char* output_names[] = {"output"};
auto outputs = session.Run(Ort::RunOptions{nullptr}, input_names, &input, 1, output_names, 1);
// outputs[0] 就是最终输出张量
```

### 阶段 5：取结果
从 `Ort::Value` 里取出数据指针和形状。

```cpp
float* out_data = outputs[0].GetTensorMutableData<float>();
auto type_info = outputs[0].GetTensorTypeAndShapeInfo();
auto out_shape  = type_info.GetShape();
```

## 3. 算子在流程中的「位置」

把上面 5 个阶段拆开看，算子出现在两个不同的时机：

| 时机 | 发生的事 | 是否真正计算 |
|------|---------|-------------|
| **Stage2 建 Session** | ORT 扫描图节点，用「算子注册表」为每个节点**绑定一个 Kernel**（CPU/GPU 实现），并做图优化、算子融合、形状推导 | ❌ 不计算，只规划 |
| **Stage4 Run** | ORT 按拓扑顺序**调用每个 Kernel 的 Compute**，把输入张量加工成输出张量 | ✅ 真正计算 |

形象地说：**Session 建立 = 给每个「算子（Node/Operator）」派发一个「执行器（Kernel）」，Run = 把所有执行器按顺序跑一遍。**

## 4. 最小可用示例（C++ 伪代码，基于本仓库头文件）

```cpp
#include <onnxruntime_cxx_api.h>
#include <vector>

int main() {
    Ort::Env env(ORT_LOGGING_LEVEL_WARNING, "demo");

    Ort::SessionOptions options;
    options.SetGraphOptimizationLevel(GraphOptimizationLevel::ORT_ENABLE_ALL);

    // 1. 加载模型（建图 + 绑定算子 Kernel）
    Ort::Session session(env, "mnist.onnx", options);

    // 2. 准备输入张量
    constexpr int64_t in_dim = 28 * 28;
    std::vector<float> input(in_dim, 0.5f);
    std::vector<int64_t> in_shape{1, 1, 28, 28};
    auto mem_info = Ort::MemoryInfo::CreateCpu(OrtArenaAllocator, OrtMemTypeDefault);
    Ort::Value input_tensor = Ort::Value::CreateTensor<float>(
        mem_info, input.data(), input.size(), in_shape.data(), in_shape.size());

    // 3. 执行推理（触发算子执行）
    const char* input_names[]  = {"input"};
    const char* output_names[] = {"predict"};
    auto outputs = session.Run(Ort::RunOptions{nullptr},
                               input_names, &input_tensor, 1,
                               output_names, 1);

    // 4. 读取结果
    auto& out = outputs.front();
    const auto info = out.GetTensorTypeAndShapeInfo();
    auto shape = info.GetShape();                 // 输出形状
    auto out_data = out.GetTensorMutableData<float>(); // 输出数据
    return 0;
}
```

## 5. 与仓库头文件的对应关系

| 概念 | 头文件中的类型/函数 |
|------|--------------------|
| 运行环境 | `Ort::Env`（[onnxruntime_cxx_api.h](file:///workspace/onnxruntime1.26.0-win/onnxruntime_cxx_api.h)） |
| 会话选项 | `Ort::SessionOptions` |
| 会话 | `Ort::Session` |
| 输入/输出值 | `Ort::Value` |

| 执行 | `session.Run(...)` |

## 6. 自测题（用于掌握本知识点）

1. 建 Session 和 `Run` 之间，算子被「绑定」还是被「执行」？为什么说 Session 建立阶段不算推理？
2. `Run` 的输入参数里，`&input` 传的是 `Ort::Value*` 还是 `Ort::Value`？`input_names` 和 `output_names` 起什么作用？
3. 把 `Ort::Value` 换成普通 `std::vector` 直接传给 `Run` 可以吗？为什么不行？（提示：ORT 需要张量的形状与类型信息）

<details>
<summary><b>参考答案</b></summary>

1. **是「绑定」，不是「执行」**。建 `Session` 时 ORT 做三件事：反序列化模型 → 载入并**图优化** → 为每个算子节点**链接对应的 Kernel**；此时不做任何数值计算，所以不算推理。真正的推理从 **`Run`** 开始，才逐个执行 Kernel。
2. 传的是 **`Ort::Value*`**（`&input` 是一个 `Ort::Value` 的地址，`Run` 的形参类型是 `const Ort::Value**` / `const char* const*` 这类指针）。`input_names[]`（输出同理 `output_names[]`）用来**指定每个名称对应的输入/输出**：ORT 用名称去模型图里找名为 `"input"` 的图输入，把它和数组里那个 `Ort::Value` 关联起来（个数与名称顺序一一对应）。
3. **不行**。`Ort::Value` 不只是"数据"，它额外携带**张量形状、数据类型、内存位置/分配方式**等元信息。`Run` 需要这些信息才知道"给算子喂多少数据、按什么排布、数据在 CPU 还是 GPU"。普通 `std::vector` 只有一段连续内存，缺这些元信息，ORT 无法按约定格式解释它。

</details>
